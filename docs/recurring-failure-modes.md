# 반복된 실패 유형 세 가지

> 이 저장소가 **같은 실수를 여러 번** 했다. 유형을 적어 두고, 유형마다 코드로 된
> 가드를 하나씩 붙였다. 새 규칙·새 수집기·새 게이트를 만들 때 이 문서를 먼저 본다.

## 1. 표면 예시를 인코딩하고 통사 프레임을 놓친다 (3회)

| 회차 | 무엇을 박았나 | 결과 |
|---|---|---|
| C-8 초판 | `not X but Y` 문자열 | 재현율 **0/6** |
| 렉시콘 초판 | Kobak 초과 어휘 407건 전수 | 평범한 영어에 **142건/1k** 오발화 |
| EN-1 초판 | `highlight`·`underscor`·`reflect` 동사 목록 | 인간·AI 모두 **0.00** — 블로그 장르의 분사였고 학술 초록은 다른 동사를 쓴다 |

**공통 원인**: 눈에 띈 예시를 그대로 정규식에 옮겼다. 패턴의 정체는 어휘가 아니라
**통사 구조**인데, 어휘는 장르·모델이 바뀌면 통째로 갈린다.

**가드**: 규칙 행에 프레임을 명시하고 계약 테스트로 요구한다
(`tests/test_en_rulebook.py::test_en3_states_the_syntactic_frame`,
`test_c8_lists_multiple_syntactic_frames`). EN-1 은 프레임(`, VERB-ing`)으로
바꾸자 AUC 0.605 → 0.726 이 됐다.

## 2. 조용한 폴백 · 느슨한 통과 (3회)

| 회차 | 무엇이 조용했나 | 결과 |
|---|---|---|
| SSC 수집기 | 본문 컨테이너를 못 찾으면 **페이지 전체**로 폴백 | 사이드바 아카이브·광고가 코퍼스에 들어가 인간 분산 107.78 |
| G4 과소윤문 게이트 | 렉시콘 단어 **하나**만 빠져도 개선으로 인정 | 변경률 0.5% 짜리 윤문을 통과 |
| live 러너 | 어느 사본이 응답했든 결과를 수용 | 6월의 v1.5.0 사본을 몇 달간 테스트 |

**공통 원인**: 실패했을 때 "그럴듯한 무언가"를 돌려주게 만들어 두면, 실패가
성공처럼 보인다. 조용한 오염이 표본 부족보다 나쁘다.

**가드**: 못 찾으면 **버린다**(SSC), 판별력이 확인된 신호로만 판정한다(G4),
버전을 대사해 어긋나면 실패로 처리한다(live 러너). 각각 회귀 테스트가 붙어 있다.

## 3. 환경 드리프트 (3회)

| 회차 | 무엇이 샜나 | 결과 |
|---|---|---|
| 코퍼스 생성 | 부모 세션 환경변수 4종 | AI 코퍼스 **33~41% 오염**(메타 발화) |
| live 테스트 | 전역 스킬 심링크가 별도 설치본 | 저장소가 아니라 **v1.5.0** 을 측정 |
| 문서 수치 | 코드·baseline 만 갱신 | README·룰북이 옛 분리도(1.33)를 인용 |

**공통 원인**: "내 환경에서 되는 것"과 "코드가 맞는 것"을 구분하지 않았다.

**가드**: `_clean_env()` 로 부모 상태를 지우고 저장소 밖에서 생성한다,
`--plugin-dir` + 버전 대사로 대상 코드를 못박는다, `test_en_docs_sync` 가 코드·
baseline·문서가 같은 수를 인용하는지 검사한다.

## 왜 결함이 많아 보이는가

**세지 않던 것을 세기 시작하면 결함이 드러난다.** 위 아홉 건 중 여섯은 이번 회차
이전부터 있었고 그동안 아무 신호도 내지 않았다. live 스위트는 몇 달간 초록불이었고,
G4 는 만들어진 날부터 판별력 없는 지표로 판정하고 있었다.

발견 속도는 코드 품질이 아니라 **측정량의 함수**다. 그래서 이 저장소는 결함 수를
줄이는 대신 **결함이 조용히 지나가지 못하게** 만드는 쪽을 택한다 — 사전 등록,
결정적 게이트, 계약 테스트.
