# 워터마킹 품질 영향 계측 — 런북

> 이 문서는 **몇 달 뒤의 나**를 위한 것이다. 그때쯤이면 왜 이 스냅샷을 떴는지 기억나지 않을 것이다.

## 한 줄 요약

워터마킹 소급 적용 **이전**에 한국어 윤문 품질 지문을 떠 뒀다. 소급 적용이 확인되면 같은 명령을 다시 돌려 대조한다. 그게 "워터마킹이 한국어를 어색하게 만들었는가"에 답하는 유일한 방법이다.

## 배경 (2026-08 시점 사실)

| 항목 | 내용 |
|---|---|
| 발표 | 2026-08-11, Anthropic |
| 방식 | SynthID-Text (Google DeepMind). 단어를 바꾸는 게 아니라 **동등한 후보 사이에서 뽑는 난수의 출처**를 키 기반 결정값으로 교체 |
| 근거 | EU AI Act 투명성 의무 (2026-08-02 발효). 적용은 전 세계 동일 |
| 대상 | 2026-08-02 **이후 출시 모델**부터. 이전 모델은 "수개월에 걸쳐" 소급 적용 |
| 촬영 시점 현행 모델 | Sonnet 5 = 2026-06-30, Opus 5 = 2026-07-24 → **둘 다 기준일 이전 출시** |
| 탐지 API | 미공개 ("곧 제공" 발표만) |

품질에 대한 학술적 기대치: SynthID-Text의 non-distortionary 모드는 출력 분포를 기댓값 기준으로 보존하도록 설계됐고, Gemini 라이브 응답 약 2천만 건 피드백으로 품질 저하 없음이 보고됐다(Nature, 2024). **다만 한국어 특화 검증치는 공개된 바 없다.** 그래서 직접 잰다.

## 언제 재촬영하는가

다음 중 하나라도 해당하면:

1. Anthropic이 **탐지 API를 공개**했을 때 (그때는 워터마크 유무를 직접 확인할 수 있다 — 최우선)
2. 8월 2일 **이후 출시된 새 모델**을 주력으로 채택할 때
3. 구형 모델 소급 적용 완료가 공지됐을 때
4. 위 소식 없이도 **3개월이 지났을 때** (소급 적용이 조용히 진행됐을 수 있다)

## 재촬영 절차

```bash
cd ~/humanize-ko

# 1) 이전 스냅샷 확인
ls tests/baselines/

# 2) 같은 조건으로 재촬영 — 모델·K·픽스처가 같아야 비교가 성립한다
python3 scripts/eval_baseline.py --k 3 --label post-watermark

# 3) 대조
python3 scripts/eval_compare.py \
    tests/baselines/2026-08-17-pre-watermark.json \
    tests/baselines/<새로 생긴 파일>.json
```

### 조건을 바꾸지 말 것

`--models`·`--k`·픽스처 집합이 이전과 다르면 비교가 무의미하다. 이전 스냅샷의 `models`·`k`·`fixtures` 필드를 먼저 열어 보고 맞춰라.

## 결과 읽는 법

`eval_compare.py`는 K회 반복의 자체 표준편차를 **잡음 바닥**으로 삼고, 그 2배를 넘는 차이만 `유의`로 표시한다.

| 판정 | 뜻 | 할 일 |
|---|---|---|
| `유의` + `[악화]` | 잡음을 넘는 악화 | K를 5~7로 올려 재촬영. 그래도 유지되면 진짜 |
| `유의` + `[개선]` | 잡음을 넘는 개선 | 다른 변경(룰북·모델 업그레이드)이 섞였는지 확인 |
| `잡음` | 흔들림 범위 안 | 변화 없음으로 읽는다 |
| `동일` | 완전 일치 | 〃 |
| `판정불가` | K=1이라 잡음 바닥을 못 쟀다 | K≥2로 다시 |
| `불변식하락` | 보호 토큰·register 보존율이 떨어졌다 | 잡음 무관, 즉시 조사 |

**유의 표시는 결론이 아니다.** 표본이 작으므로 이건 통계적 검정이 아니라 보수적 눈금이다. 재촬영·표본 증가의 신호로 읽어라.

### 교란 요인 (반드시 통제)

대조 결과를 워터마킹 탓으로 돌리기 전에 이것들부터 배제하라:

- **룰북·스킬 변경** — 스냅샷의 `git_commit`을 비교하라. 다르면 그 차이가 원인일 수 있다. 가능하면 이전 커밋을 체크아웃하고 재촬영하라.
- **모델 자체의 업그레이드** — 같은 별칭(`claude-sonnet-5`)이 다른 스냅샷을 가리킬 수 있다.
- **비결정성** — 이게 K≥3을 강제하는 이유다.

이 셋을 배제하지 못하면 "워터마킹 때문"이라고 말할 수 없다. 그냥 "달라졌다"까지만 말하라.

## 이 도구의 한계 (솔직하게)

- **워터마크 유무를 직접 확인하지 못한다.** 탐지 API가 없다. 촬영 시점에 소급 적용이 이미 왔는지도 모른다. 그래서 `pre-watermark` 라벨은 **추정**이지 확인이 아니다.
- **품질을 재는 게 아니라 신호를 센다.** change_rate·피동 카운트·register 보존은 대리 지표다. "읽었을 때 어색한가"는 결국 사람이 봐야 한다 — 그래서 스냅샷에 `output` 원문을 통째로 보존한다. 대조에서 유의가 뜨면 그 원문을 직접 읽어라.
- **픽스처 6개는 적다.** 커버리지가 좁다. 유의한 차이가 보이면 픽스처를 늘려 재확인하라.

## 관련 결정

워터마크 **제거**는 탑재하지 않기로 했다. 사유는 `CLAUDE.md`의 「AI 워터마킹에 대한 입장」 참조. 요지: 탐지기가 없어 측정할 수 없고, 측정 못 하는 제거는 맹목적 단어 흔들기이며, 그건 이 프로젝트의 목적과 정면으로 충돌한다.
