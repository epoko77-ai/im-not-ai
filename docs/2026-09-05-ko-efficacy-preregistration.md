# 한국어 윤문 효능 측정 — 사전 등록 (2026-09-05)

> **실행 전에 작성해 커밋한다.**
> 실행: `python3 scripts/eval_ko_efficacy.py --run 12 --report`

## 왜 하는가 — 영어에서 역수입한다

영어 쪽에서 효능을 재고 나서 드러난 사실: **한국어도 효능을 잰 적이 없다.**

한국어에는 81패턴·8장르 셀·golden 픽스처·live 테스트가 있지만, 그 전부가
"망가지지 않았나"(안전)와 "AI 글을 골라내는가"(판별)를 잰다. **"고친 뒤 사람 글에
가까워졌는가"는 어디에도 없다.** 영어에서 쓴 방법을 그대로 가져온다 —
사전 등록 → 대조군 → 홀드아웃.

한국어가 영어보다 유리한 점이 하나 있다: **인간 baseline 이 이미 있다**
(KatFish 인간 470편 + 사용자 코퍼스, 장르별 평균·표준편차). 그래서 "인간 쪽으로
움직였나"를 **z-score 가 0 에 가까워졌는가**로 직접 잴 수 있다.

## 설계

| 팔 | 내용 | n |
|---|---|---|
| **A. 스킬** | `humanize-korean` 정상 실행(shim·게이트 포함) | 12 |
| **B. 맨 프롬프트** | "AI 티 없이 사람이 쓴 것처럼 자연스럽게 고쳐줘" | 12 |
| (입력) | 같은 제목으로 생성한 한국어 AI 초안 12편 | |

- 두 팔 같은 모델(`claude-sonnet-5`).
- 입력 생성·윤문 모두 저장소 밖에서, 부모 세션 환경변수를 지우고 실행한다.

## 주 판정 지표

`skills/humanize-korean/references/baseline.json` 의 장르 셀 대비 **z-score**.
대상은 S1 후보 5종(`verify_gates.py` 와 같은 목록):

`comma_inclusion_rate` · `comma_usage_rate` · `ending_comma_rate` ·
`comma_segment_length` · `hanja_nominalizer_density`

**좋아짐의 정의**: 윤문 전 |z| 가 1.0 을 넘던 지표의 |z| 가 줄어드는 것.
z 가 이미 인간 범위(|z| ≤ 1.0)인 지표는 판정에서 제외한다 — 고칠 이유가 없다.

## 성공 기준 (사전 확정)

1. **K1 이동** — 대상 지표에서 짝비교 부호검정 **p < 0.05**, |z| 감소 방향
2. **K2 안전** — `scripts/checks.py` 실패(수치 주입·인용 훼손·각주·격식 역주행) **0건**,
   서법 소실(`verify_gates.py` P5) **0건**
3. **K3 과윤문 아님** — 변경률 중앙값 < 30%, 50% 초과 0건
4. **K4 대조군 우위** — 맨 프롬프트(B) 대비 K2 위반이 같거나 적을 것

넷 다 충족하면 **"한국어 경로의 효능이 확인됐다"**고 적는다. 하나라도 미달이면
미달로 적는다. 영어와 마찬가지로 **"사람이 읽기에 나아졌는가"는 재지 못한다.**

## 예상되는 결과와 그 해석

영어 스킬은 "정밀하지만 작다"였다(변경률 0.5~1.2%, 위반 0%). 한국어는 규칙이
81개·처방집이 212줄이므로 **편집량이 더 클 것으로 예상한다.** 그 예상이 빗나가면
— 한국어도 작게 고친다면 — 편집량의 원인은 규칙 수가 아니라 **철칙 #2(탐지된
구간만 손댄다)의 구조적 귀결**이라는 뜻이 된다. 어느 쪽이든 기록한다.
