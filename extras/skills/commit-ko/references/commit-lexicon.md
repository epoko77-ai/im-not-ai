# commit-ko 치환표

> 이 표는 `skills/humanize-korean/references/ai-tell-taxonomy.md`의 A-7("가지고 있다" / light verb construction)·A-8(이중 피동)·A-9(by-passive "~에 의해")·A-12("만들어지다"/"이루어지다", 자동화된 피동)·F-4(과잉 접두·접미, 한자어 명사화 -성·-적·-화)를 **원본 SSOT**로 삼아, 커밋 메시지처럼 짧고 명사형 종결이 관용인 register에 맞게 파생시킨 소형 참조표다. taxonomy 본진이 갱신되면(신규 패턴 승격 등) 이 표도 함께 점검할 것 — 중복 관리가 아니라 파생 관계임에 유의. `scripts/check_commit_lexicon_ids.py`가 이 헤더 선언과 아래 표 본문의 ID 인용이 정확히 일치하는지 검사한다.
>
> 1~4절은 한국 업무 문서투 격식(사무적 표현) 문제고, **5절이 진짜 "영어 직역 번역투"**(by-passive·이중피동·have 직역 등 구문 계열) 문제다. 둘은 원인이 달라 구분해서 다룬다.

## 1. 격식 동사 남용 (light verb construction의 커밋 register 특화)

일반 산문에서는 "가지고 있다"류 영어 직역이 문제였다면, 커밋 메시지에서는 한국 업무 문서투 격식 동사("수행/진행/실시/완료" + "하다/함/하였습니다")가 같은 자리를 차지한다.

| AI/사무적 표현 | 자연스러운 커밋 표현 |
|---|---|
| "~을 수행함" | "~함" |
| "~을 진행함" / "~을 진행하였습니다" | "~함" / 동사 그대로 (예: "리팩터링을 진행함" → "리팩터링") |
| "~을 실시함" | "~함" |
| "~작업을 완료하였습니다" | "~함" (예: "버그 수정 작업을 완료하였습니다" → "버그 수정") |
| "~을 적용함" (내용이 없는 채움용일 때) | 구체 동사로 (예: "새 설정을 적용함" → "새 설정 반영") |

## 2. 한자어 명사화 (-성·-적·-화) — F-4 처방 그대로 적용

| AI/사무적 표현 | 자연스러운 커밋 표현 |
|---|---|
| "안정성 개선을 진행" | "안정성 개선" |
| "구조적 변화를 실시" | "구조 변경" |
| "효율화 작업을 수행함" | "효율화" / "성능 개선" |

## 3. 과공손·과격식 종결

커밋 메시지는 격식체(-습니다)보다 명사형·평서형 종결("~함", "~수정", "~추가")이 관용이다. 원문이 이미 구어체·평서형이면 오히려 손대지 않는다(humanize-korean 철칙 #5, register 보존 — 격상 금지와 동일 원칙).

| AI/사무적 표현 | 자연스러운 커밋 표현 |
|---|---|
| "~하였습니다" | "~함" |
| "~수정하였음" | "~수정" |
| "~을 반영하였습니다" | "~반영" |

## 4. 장황한 명사구

| AI/사무적 표현 | 자연스러운 커밋 표현 |
|---|---|
| "버그 수정 작업을 완료하였습니다" | "버그 수정" |
| "문서 업데이트 작업을 진행함" | "문서 업데이트" |
| "테스트 코드 추가 작업을 수행함" | "테스트 코드 추가" |

## 5. 번역투 구문 (영어 직역 구조) — A-7·A-8·A-9·A-12 계열

한국 업무 문서투(1~4절)와 달리, 아래는 영어 문장 구조를 그대로 옮겨서 생기는 진짜 "번역된 티"다. 커밋 메시지에도 그대로 새어 나온다.

| AI/번역투 표현 | 자연스러운 커밋 표현 | 근거 |
|---|---|---|
| "사용자**에 의해** 트리거되는 버그 수정" | "사용자가 트리거하는 버그 수정" | A-9 by-passive — 행위자를 주어로 복귀 |
| "설정값이 검증**되어지는** 로직 추가" / "검증**되어지도록** 수정" | "설정값 검증 로직 추가" | A-8 이중 피동 — 단일 피동 또는 능동으로 |
| "새 캐시 레이어를 **가지도록** 구조 변경" | "캐시 레이어를 추가하도록 구조 변경" | A-7 "가지고 있다"(have 직역) — 동사 환원 |
| "테스트가 실패**하게 되는** 원인 제거" | "테스트 실패 원인 제거" | A-12 자동화된 피동 — 능동 서술로 |

## 적용 시 주의

- Conventional Commits의 `type(scope):` 접두사, 이슈 번호(`#123`), 파일·함수·변수명은 치환 대상이 아니다 — 그대로 보존.
- **개발 용어로 굳은 외래어(업데이트·리팩터링·버그·이슈·머지·커밋·롤백 등)는 치환 대상이 아니다.** 이 register에서는 이런 외래어가 오히려 자연스러운 관용어이므로, 순우리말로 바꾸면 humanize-korean 철칙 #5(register 보존)를 어기고 더 어색해진다. "번역투"는 어휘의 출신(외래어냐 아니냐)이 아니라 5절 같은 **구문 구조**(by-passive·이중피동·have 직역)의 문제다.
- 위 표에 없는 패턴이라도 "사무 보고서투 격식 동사 + 명사화 어휘" 또는 "영어 구문을 그대로 옮긴 피동·have류 구조"라는 공통 신호가 보이면 같은 원칙(짧은 동사·능동·명사형 종결로 환원)을 적용해도 된다. 단, 의미·범위를 벗어나는 재작성은 금지.
